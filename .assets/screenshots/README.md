## 📘 Overview

I use this folder to keep **screenshots that document my real learning and development process**.

Instead of placing screenshots randomly across the repository, I organize them by topic so each README, guide, module, or project can reference the correct visual evidence.

Screenshots are especially useful when a concept is easier to understand by **seeing the actual interface, installer, terminal result, configuration screen, or completed output**.

> [!NOTE]
> This folder is for screenshots and captured interface images. General illustrations and decorative graphics belong in the appropriate `.assets/images/`, `.assets/banners/`, or other media folders.

---

## 🧠 Why Screenshots Matter

Screenshots make technical documentation easier to follow because they help me:

- show exactly what a beginner should expect to see;
- document installation steps visually;
- demonstrate configuration screens;
- preserve terminal and program output;
- provide evidence of completed work;
- explain interfaces without relying only on text;
- make README files clearer and more professional.

## 🛠️ How I Organize Screenshots

Each screenshot collection should have:

1. a clearly named topic folder;
2. descriptive image filenames;
3. a `README.md` explaining what the screenshots document;
4. images ordered in the same sequence as the guide that uses them.

For example:

```text
vscode-install/
├── README.md
├── 01-download-vscode.png
├── 02-vscode-installer-exe.png
├── 03-license-agreement.png
├── 04-select-additional-tasks.png
├── 05-ready-to-install.png
├── 06-installing-vscode.png
└── 07-complete-and-launch.png
```

---

## 🧪 Naming Convention

I use clear, ordered filenames so screenshots are easy to identify and appear in logical order.

### Recommended format

```text
NN-short-descriptive-name.png
```

Examples:

```text
01-download-vscode.png
02-vscode-installer-exe.png
03-license-agreement.png
04-select-additional-tasks.png
```

### Why I use numbers

The numeric prefix makes the order obvious when:

- browsing the folder;
- writing installation guides;
- reviewing the learning process;
- referencing images from Markdown.

> [!TIP]
> A screenshot filename should explain what the image shows without requiring someone to open it first.

---

## 🚀 Using Screenshots in README Files

From another README, I reference the screenshot using the correct relative path.

Example:

```html
<p align="center">
  <img src="../../../.assets/screenshots/vscode-install/03-license-agreement.png"
       alt="Visual Studio Code license agreement screen"
       width="80%">
</p>
```

I also include useful `alt` text so the purpose of the screenshot remains understandable if the image cannot be displayed.

## ✅ Screenshot Workflow

```text
Capture the important screen
        ↓
Choose the correct screenshot collection
        ↓
Rename the file clearly
        ↓
Keep screenshots in logical order
        ↓
Reference the image from the relevant README
        ↓
Add a short explanation below or above the image
```

---

## 📌 Guidelines I Follow

- I keep screenshots relevant to the topic.
- I avoid duplicate images when one screenshot already explains the step clearly.
- I use readable, descriptive filenames.
- I keep installation screenshots in chronological order.
- I do not use screenshots only as decoration.
- I add screenshots where they make instructions easier to understand.
- I keep visual assets separated from source code.
