## 1. How SQL Sentences Work

SQL is a language. Like an English sentence, the words have roles and their order matters.

```sql
INSERT INTO teachers (name)
VALUES ('Peyman');
```

| Exact token | English meaning | Its job |
| --- | --- | --- |
| `INSERT` | Add/place | Starts an operation to add rows |
| `INTO` | Into a destination | Introduces the target table |
| `teachers` | Name of table | Where the row goes |
| `(name)` | Column list | Which field receives data |
| `VALUES` | Values to provide | Starts the row of supplied data |
| `('Peyman')` | One text value | Corresponds to the `name` column |
| `'` | Single quotation mark | Surrounds a SQL string literal |
| `;` | End | Ends the SQL statement |

**Why `INSERT INTO` and not just `INSERT`?** SQL has defined grammar. The conventional PostgreSQL insertion form is `INSERT INTO table_name (columns) VALUES (values)`. `INTO` links the INSERT operation to its destination.

**Why `VALUES` (plural) for one value?** `VALUES` is the PostgreSQL SQL keyword whether you insert one value, several columns, or multiple rows. The phrase "a value" describes a single data item; the statement uses the keyword `VALUES`.

## 2. Before INSERT: CREATE TABLE

```sql
CREATE TABLE teachers (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL
);
```

| Token / phrase | Meaning and behavior |
| --- | --- |
| `CREATE` | Make a new database object |
| `TABLE` | The object type: a table |
| `teachers` | The table identifier |
| `(` and `)` | Enclose column definitions |
| `id` | A column name; not a special SQL keyword |
| `INTEGER` | Whole-number data type |
| `GENERATED` | Defines database-generated column behavior |
| `ALWAYS` | Usually require generated values rather than explicit ones |
| `AS IDENTITY` | Use an associated database sequence to generate an ID |
| `PRIMARY KEY` | Enforce unique, non-NULL identifiers |
| `,` | Separate column definitions |
| `name` | Another column name |
| `TEXT` | Text data type |
| `NOT NULL` | Reject the SQL NULL value |
| `;` | Statement terminator |

The creation command produces the structure, not student or teacher records.

## 3. Understand VALUES and Column Order

```sql
INSERT INTO teachers (id, name)
VALUES (7, 'Ali');
```

- First column `id` receives first value `7`.
- Second column `name` receives second value `'Ali'`.
- Commas separate columns and corresponding values.
- For the earlier `GENERATED ALWAYS` table, this **explicit ID would be rejected** unless a special override is used.

With a `GENERATED BY DEFAULT AS IDENTITY` table, explicitly specifying `7` can be allowed if unique.

Multiple rows:

```sql
INSERT INTO teachers (name)
VALUES ('Ali'), ('Sara');
```

Each parenthesized set after VALUES is one row.

## 4. PRIMARY KEY Is Not the Same as IDENTITY

```sql
id INTEGER PRIMARY KEY
```

Ensures uniqueness and non-NULL, **but does not auto-generate IDs in PostgreSQL**.

```sql
id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

Adds an identity generator. The ID is generated when omitted from the INSERT. PRIMARY KEY still separately controls uniqueness.

## 5. ALWAYS vs BY DEFAULT

```sql
id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

Usually refuses explicit values such as:

```sql
INSERT INTO teachers (id, name)
VALUES (50, 'Peyman');
```

```sql
id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

Allows explicit ID values by default, while generating one if the ID is omitted. **Manual IDs do not automatically advance the sequence.**

## 6. OVERRIDING SYSTEM VALUE — Every Word

Use only in a safe, isolated PostgreSQL practice database:

```sql
INSERT INTO teachers (id, name)
OVERRIDING SYSTEM VALUE
VALUES (50, 'Peyman');
```

This example presumes the table uses `GENERATED ALWAYS AS IDENTITY`.

| Keyword | What it communicates |
| --- | --- |
| `OVERRIDING` | Override normal behavior for this INSERT |
| `SYSTEM` | The database system normally controls the generated ID |
| `VALUE` | Explicitly supplied value, in this special clause's singular wording |
| `VALUES` | Separate SQL keyword introducing the actual row data |

**Important distinction:** `OVERRIDING SYSTEM VALUE` is a clause with singular `VALUE`; `VALUES` is the separate plural keyword before `(50, 'Peyman')`.

The command allows the manually provided ID of 50, but it **does not disable** PRIMARY KEY, NOT NULL, CHECK, or other constraints. If ID 50 is already present, PostgreSQL rejects the insert.

## 7. NULL Is Different from an Empty String

- `NULL`: an unknown or missing SQL value.
- `''`: a valid zero-character string, not NULL.
- `' '`: a string containing one space.
- `NOT NULL` excludes the first one, not the other two.

## 8. Why a Sequence Can Skip Numbers

Identity columns use sequences. Generating a value advances the sequence even if a later constraint violation makes the INSERT fail. Deleting a row doesn't normally rewind the sequence.

Example: A manual ID of 1 is inserted into a BY DEFAULT identity table; the next generated ID may still be 1 and fail on PRIMARY KEY. The following generated ID may be 2.

Do not treat an ID as a count of rows. `SELECT COUNT(*) FROM teachers;` counts rows, which is different.

## 9. Common Misunderstandings

| Misunderstanding | Correction |
| --- | --- |
| PRIMARY KEY generates IDs | No. IDENTITY does that. |
| Identity values are always consecutive | No. Gaps are normal. |
| BY DEFAULT automatically checks the highest ID | No. The sequence operates separately. |
| OVERRIDING SYSTEM VALUE disables security constraints | No. It only addresses explicit values for GENERATED ALWAYS identity columns. |
| NOT NULL prevents blank strings | No. It prevents SQL NULL. |
| INSERT writes into any table without permission | No. Database permissions and applicable policies still matter. |

## 11. Safety and Learning Order

All tables and records here are examples. Do not run experimental SQL in ProTrack MX production. Learn commands in this order:

**CREATE TABLE → column names → data types → PRIMARY KEY → NOT NULL → INSERT INTO → VALUES → IDENTITY → sequences → OVERRIDING SYSTEM VALUE.**

This last clause is an advanced exception, not a prerequisite for understanding basic INSERT.
